ECE 2103 • PROJECT PURPOSE

Why Build a Web Crawler DSA-First?

1. The Real-World Engineering Problem

  • • Web as a Directed Graph: The World Wide Web is an unbounded, cyclic directed graph G = (V, E) of pages and hyperlinks.
  • • Systematic Search: Search engines require exhaustive traversal within domain boundaries without falling into infinite cyclic traps.
  • • Shortest-Path Discovery: BFS guarantees discovering pages in strictly increasing order of click distance from the seed.
  • • Ethical Scraping: Requires O(1) robots.txt policy lookups and timestamp-based polite rate limiting.

2. Why DSA-First vs High-Level Libraries?

  • • Black-Box Abstractions: Libraries like Scrapy or urllib hide queue discipline, pointer manipulation, and memory resizing.
  • • First-Principles Mastery: Custom classes expose exact memory invariants, time complexities, and performance trade-offs.
  • • Strict Invariants: Enforces FIFO frontier order, instant discovery marking, and canonical URL normalization.
  • • Pedagogical Bridge: Directly connects textbook theory (Linear Arrays, Heaps, BSTs, Graphs) to production software.
SPEAKER NOTES: The motivation behind WebTrace is twofold. Mathematically, the web is an unbounded directed graph, and exploring it requires rigorous graph traversal and cycle prevention. Computationally, standard scraping libraries abstract away how memory, queues, and sets actually function under the hood. By building WebTrace DSA-first, we implement and verify every data structure directly, ensuring complete control over algorithmic invariants.
ECE 2103 • CUSTOM DATA STRUCTURES

Textbook Data Structures Implemented (structures.py & graph.py)

Vector[T] (Linear Dynamic Array)

structures.py:31–164

• Memory Layout: Contiguous buffer with initial capacity 8; doubles on overflow.

• Amortized O(1): push_back() achieves amortized constant time; O(1) index access.

• Algorithms: Linear Search O(N) and Binary Search O(log N) on sorted items.

MinHeapPriorityQueue[T] (Binary Min-Heap)

structures.py:184–268

• Array Math: Parent(i)=(i-1)//2, Left=2i+1, Right=2i+2. Zero pointer overhead.

• Min-Heap Invariant: Parent priority <= Child priority; peek() in O(1) time.

• Heapify: push() with _sift_up O(log N), pop() with _sift_down O(log N).

BinarySearchTree[T] (Linked BST)

structures.py:284–427

• Node Architecture: Linked representation with key, value, left, and right pointers.

• 3-Case Deletion: Handles leaf node, 1 child, and 2 children via in-order successor.

• In-Order Traversal: Left -> Root -> Right yields lexicographically sorted page records.

LinkGraph & Dijkstra's Algorithm

graph.py:32–220

• Adjacency List: dict[str, list[str]] requiring O(|V| + |E|) space vs O(|V|^2) matrix.

• Edge Deduplication: Helper set table enforces O(1) parallel edge deduplication.

• Dijkstra Engine: Greedy shortest weighted path using MinHeapPriorityQueue in O((V+E)log V).

SPEAKER NOTES: In structures.py and graph.py, we built four core data structures directly aligned with the syllabus. The Vector simulates contiguous memory management and dynamic resizing. The Min-Heap implements array-based complete binary trees for Dijkstra's shortest path algorithm. The BST provides key-value page indexing with all three deletion cases, and LinkGraph models the web as an adjacency list graph requiring optimal O(|V| + |E|) space.
ECE 2103 • TRAVERSAL INVARIANTS

Frontier Discipline & Key Algorithmic Invariants

1. FIFO Frontier Queue

crawler.py:99 • collections.deque

• FIFO Discipline: Append to rear, popleft from front (both O(1)).

• Level-Order Invariant: All pages at depth d are visited before depth d + 1.

• Shortest Hop Path: Guarantees minimum click path from seed URL.

2. Visited Tracking & Cycles

crawler.py:100, 184–192 • Vector & Set

• Cycle Prevention: Prunes cyclic loops (A -> B -> A) and self-links.

• Discovery Timing: Marked visited IMMEDIATELY upon discovery, not dequeue, eliminating duplicate queue bloat.

• Domain Boundary: Enforces subgraph restriction via is_same_domain().

3. Hash Caching & URL Normalization

fetcher.py:72–74 • url_utils.py:83–160

• robots.txt Cache: Caches parsed policies per domain root for O(1) check.

• Politeness Map: Tracks last request time to enforce delay interval.

• Canonical Invariant: Normalizes scheme, port, and fragments (#) so identical pages share identical hash keys.

SPEAKER NOTES: Crucial to any graph traversal are its invariant rules. The FIFO queue ensures BFS level-order traversal, guaranteeing shortest hop paths. The visited tracking mechanism must mark vertices upon discovery rather than expansion; otherwise, a dense mesh would cause exponential queue bloat. Finally, URL normalization guarantees that semantically identical pages produce identical hash keys in our lookup maps.

ECE 2103 • EXECUTION PIPELINE

Crawler Execution Lifecycle: End-to-End BFS Pipeline

1. Input & Normalization Canonicalize seed URL (strip fragments, lowercase scheme/host, standardize trailing slash).
2. Frontier Initialization Enqueue CrawlTask(seed, depth=0); mark in Visited Vector; insert root node in LinkGraph.
3. FIFO Dequeue (popleft) Pops pending task from front of queue, guaranteeing strict level-order BFS traversal.
4. Boundary & Politeness Check If depth > max_depth, skip. Consult robots.txt hash map; sleep if politeness delay active.
5. Fetch & Measure Latency HTTP GET page; measure elapsed network time (ms) as edge weight for Dijkstra shortest paths.
6. Tokenize & Extract HTML Extract page title, text blocks, quote elements, download documents (PDF/ZIP), and anchor hrefs.
7. Domain Filter & Edge Insertion Discard off-domain URLs. For internal links, add directed edge (u -> v, weight=ms) into LinkGraph.
8. Discovery-Time Enqueue If norm_link not in visited: push_back into Visited Vector and append CrawlTask(norm_link, depth+1).
9. BST Lexicographical Indexing Insert CrawledPage record into BinarySearchTree keyed by canonical URL for O(log N) retrieval.
10. Serialization & Artifact Export Dump BFS tree metadata to crawled_pages.csv and complete adjacency list to link_graph.json.
SPEAKER NOTES: This pipeline represents the end-to-end lifecycle of a crawl task. We begin with URL canonicalization, initialize the FIFO queue, and enter the main BFS loop. For each dequeued URL, we respect robots.txt and politeness, record network latency for Dijkstra edge weights, parse outgoing links, add edges to the adjacency list, and immediately enqueue unseen domain-internal links. Finally, pages are indexed in a BST and serialized to disk.

Dijkstra Shortest Path Trace (test_syllabus_dsa.py)

• Graph Setup: /home to /destination

Route A: /home ->(10ms)-> /fast_route ->(5ms)-> /dest [15ms]
Route B: /home ->(2ms)-> /slow_route ->(30ms)-> /dest [32ms]

• Unweighted BFS: Sees both as 2 hops; cannot find the latency-optimal path.

• Min-Heap Extraction: 0ms (/home) -> 2ms (/slow) -> 10ms (/fast) -> 15ms (/dest).

• Optimal Path: ['/home', '/fast_route', '/destination'] (Cost: 15.0ms)

BST In-Order Lexicographical Sorting

• Arbitrary Insertion Sequence:

/page_z, /page_a, /page_m, /page_b, /page_c

• BST Invariant: Left subtree < Root < Right subtree.

• In-Order Traversal (Left -> Root -> Right):

/page_a, /page_b, /page_c, /page_m, /page_z

• Linear Sorting: Yields strictly ascending lexicographical order in O(N) traversal time without external sorting!

SPEAKER NOTES: This slide demonstrates the power of our custom data structures. In Dijkstra's algorithm, unweighted BFS would fail to distinguish between a fast 15-millisecond route and a slow 32-millisecond route because both take two hops. Our Min-Heap priority queue correctly selects the optimal weighted path. Meanwhile, the Binary Search Tree indexes pages as they are crawled, and an in-order traversal sorts them alphabetically in linear time without calling Python's sort.

ECE 2103 • VIVA VOCE Q&A

Examiner Viva Voce Q&A: Traversal & Graph Theory

Q1: Why choose BFS over DFS for a web crawler?

• BFS: Discovers pages in order of shortest click-depth from root.

• DFS Trap: DFS gets trapped down infinite deep branches (dynamic calendar links, infinite pagination), missing peer pages.

Q2: Why an Adjacency List over an Adjacency Matrix?

• Space Bound: O(|V| + |E|) space vs O(|V|^2) matrix.

• Web Sparsity: Since |E| << |V|^2, a matrix with 10,000 pages would waste 100M entries. Neighbor iteration takes O(deg(u)) vs O(|V|).

Q3: Why must URLs be canonicalized before hashing?

• Collision Invariant: Distinct URL strings can refer to the same document (fragments #, uppercase host, relative paths).

• Impact: Without normalization, visited sets store duplicate keys, causing redundant network fetches and infinite cycles.

Q4: When is a URL marked visited—discovery or expansion?

• Discovery Time: Must be marked visited IMMEDIATELY upon discovery (before enqueuing).

• Exponential Trap: If delayed until dequeue, parallel paths enqueue the same URL dozens of times, causing exponential frontier bloat.

SPEAKER NOTES: Examiners frequently ask these four questions during viva voce evaluations. The key points to emphasize are: BFS guarantees shortest click paths whereas DFS gets lost down infinite branches; the Adjacency List is optimal because the web graph is sparse; URL canonicalization protects the hash set's deduplication invariant; and marking visited at discovery prevents exponential queue bloat.

Examiner Viva Voce Q&A: Custom Data Structures & Dijkstra

Q5: How does Min-Heap map a tree into a linear array?

• Index Formula: Parent(i)=(i-1)//2, Left=2i+1, Right=2i+2.

• Complete Tree: Levels fill left-to-right with zero internal array gaps. Provides superior CPU cache locality and zero pointer overhead.

Q6: How does BST deletion handle two children?

• In-Order Successor: Finds smallest node in right subtree (_find_min).

• Value Swap & Recurse: Copies successor key/value into the deleted node, then recursively deletes the successor from the right subtree.

Q7: How does Dijkstra differ from unweighted BFS here?

• Hop vs Latency: Unweighted BFS assumes uniform edge weights. Web requests have varying latencies.

• Min-Heap Routing: Explores paths by cumulative minimum latency, finding the fastest route rather than just fewest hops.

Q8: How does WebTrace ensure polite crawling?

• robots.txt Cache: Caches parsed RobotFileParser instances per domain in a hash map to avoid redundant network queries.

• Politeness Delay: Enforces time.sleep() if elapsed time since last domain request < delay threshold.
